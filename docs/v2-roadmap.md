# Z-Agent v2 上下文与记忆路线图

本文只记录后续版本范围，不代表当前 v1 已实现。

## 1. 数据库级上下文版本

- 将进程内 `context_version` 迁移到 SQLite session 元数据，并使用事务递增。
- WorkingSet 缓存键包含数据库版本、模型配置版本和工具 schema 版本。
- 支持 Electron Core 多进程、异常重启和多个客户端共享同一数据目录。

## 2. 持久化稠密向量索引

- 保留 v1 的 Exact/FTS5 结果作为事实召回通道，不允许 embedding 单独决定证据。
- 提供可替换的中文/多语 embedding provider，记录模型名、维度和向量版本。
- 向量索引与 EventLog 使用相同 `event_id`；重建索引不修改原事件。
- 支持增量写入、批量重建、模型升级迁移、损坏回退和索引删除。
- 默认在本地持久化；调用远程 embedding 服务前明确提示数据外发范围。

## 3. 长期记忆机制

- 区分 episodic（任务经历）、semantic（稳定事实）和 procedural（用户确认的工作偏好）。
- 记忆写入必须有来源 event ID、置信度、作用域、创建原因和最后验证时间。
- 敏感内容、密钥、Thinking、provider 原始响应永不进入长期记忆。
- 用户可以查看、固定、纠正、过期和删除记忆；删除同时清理派生向量。
- 冲突事实不静默覆盖，保留版本并要求重新验证。

## 4. 验收门槛

- 中文同义表达、中英混合术语和代码标识符评测分别报告 lexical、dense 与融合指标。
- 归档/记忆引用的 event ID 与 SHA-256 必须 100% 可恢复。
- 多进程缓存一致性、索引重建、删除传播和远程 embedding 失败回退必须有功能测试。
- 任何记忆召回都不得突破工作区、会话和敏感信息边界。
